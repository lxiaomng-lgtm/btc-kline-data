# BTC 无人值守运行和验收

- 固定跨对话接口为仓库根目录的 `btc_daily.json`。读取时应检查字段的事件时间、取得时间、状态及 `valid_until_bjt`；缓存报价可能已失效。K 线以北京时间 08:00 的自然周期网格为基准，并给出已收盘与仍在形成的边界。ETF 只从已带双表核验标记的记录选择 FINAL。第三方未提供实际发布时间的字段留空。
- `pre_change_diagnosis.json` 是按已过去的 45 分钟时段逐一核对的旧版基线。GitHub 不公开未送达的计划事件，运行记录里没有对应任务不能进一步区分服务端延迟丢弃或未触发。本仓库的实测缺账和现有账本证据独立于这一不可见原因。
- 每十分钟主工作流尝试当前 45 分钟槽位，另接受近期 K 线任务成功事件、watchdog 派发和外部心跳 push。单并发写者。按信号日期和槽位去重，旧信号仅能在其仍开放时修复，必须重新确认 GitHub 已公开，并重取新盘口。空盘口留失败记录以供仍开放的槽位重试。跨槽位永远跳过，模拟成交与账本只追加。
- `daily/` 按北京时间保存质量报告，列出触发和队列状态、成交对账、接口失败、报价与信号发布时间差以及应记与有效槽位。30 天覆盖率按连续完整日期、每日至少预期 32 个槽位计算。历史可观测缺口保留。研究费用为每边 0.40% 手续费加 0.05% 额外滑点，实际账户费率待核验。
- `receipts/` 保存实时捕获记录，独立标识 Binance、OKX、Bybit、Bitstamp 和 Coinbase。OKX BTC 合约主动买卖量是币种口径，OI 的 `BTC-USDT-SWAP` 是单合约口径。两者不会替换成 Binance 或 Bybit 历史序列。现有档案仍由原工作流更新，普通自动事件停跑大规模历史分析。
- `protocol.json` 在前瞻观测前登记，`forward_progress.json` 报告逐期有效量。只有后续运行已经读到前一份已提交观测的情况下，其新行情才可成为该信号的入场参考。开发 60 日，验证 30 日，随后前瞻。各期至少 100 个非重叠且完成的样本。当前候选仅用于研究，正式 A/B/C 状态不由本任务改动。
- GitHub 的第二个 watchdog 仍依赖 GitHub 调度。外部心跳可以由已经授权的无服务器任务写入固定文件，走 GitHub push 事件。外部任务若只能每小时运行，其本身无法达到 45 分钟覆盖要求。若需外部独立分钟级触发，cron-job.org 支持 HTTP 请求，但生产验证需要独立账号和凭据授权；不得把令牌写入仓库。
